Command-Line Detections
As we know from the Beacon Command Behaviour lesson - there are many Beacon commands that work by running a new process, and these are typically started using the CreateProcessA API.


This API accepts two string parameters: lpApplicationName and lpCommandLine.  The Microsoft documentation describes the nuances of how these parameters work and how they relate to each other - but I want to focus on how they re used in a Cobalt Strike context.

Why  access denied ?
A question you may be asking yourself is why these detections surface as an access denied error, and not a more specific  defender has blocked this  error.  It s simply down to how the Windows Defender driver works.  There are kernel routines such as PsSetCreateProcessNotifyRoutineEx that allow drivers to register a callback routine when events of interest occur, such as a process being started.

In this case, the callback function receives a PPS_CREATE_NOTIFY_INFO structure which has the following members:
ImageFileName - a pointer to a string that holds the filename of the executable.
CommandLine - a pointer to a string that holds the command used to execute the process.
CreationStatus - the NTSTATUS value to return for the process-creation operation.
The driver is able to inspect both the ImageFileName and CommandLine members, and if it sees something it doesn t like  i.e. command line arguments that correspond to known abuses as detailed above , it can set CreationStatus to a non-success value, typically STATUS_ACCESS_DENIED, to prevent the process from being started.

Bypasses?
You cannot  disable  these callbacks unless you have code execution in the kernel, and that generally requires something like a kernel vulnerability or a vulnerable driver that you can exploit.  Both of these are far outside the scope of this course.  The more viable technique you can employ is to find a different procedure that achieves the same outcome.  For example, instead of running schtasks.exe with  SilentCleanup  on the command line, is there an API or COM object that can be used to trigger the task instead?
